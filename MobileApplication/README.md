# 🧊 CubePermutation AI — Mobile Client (Flutter Cross-Platform)

Production-ready cross-platform Flutter client for **CubePermutation AI**, targeting Android, iOS, Windows, macOS, Linux, and Web from a single codebase.

---

## 🏛️ Architecture & Feature Parity

The mobile application replicates the core flows, visual design tokens, and mathematical behavior of the Flask web platform:
- **Visual Design Parity:** Styled with the web platform's deep dark palette (`#090D16`, `#0D1322`, `#141C30`), glowing indigo/cyan borders (`#6366F1`, `#38BDF8`), and standard WCA Rubik's cube facelet colors (Yellow, White, Green, Blue, Orange, Red).
- **Backend as Source of Truth:** All authentication, user records, solve tracking, and image vision processing are managed by the FastAPI backend on top of the shared MySQL database. The mobile app never duplicates the database schema or acts as a divergent source of truth.
- **FastAPI Processing Gateway:** OpenCV facelet segmentation (CLAHE adaptive illumination correction + HSV color clustering) and Kociemba Two-Phase group theory solving run on the FastAPI backend and stream real-time results to the client.
- **Device Resources:** Real-time camera capture (`image_picker`), gallery photo selection, and device storage integration.
- **Offline Vault (Drift SQLite):** First use requires an active connection for login and initial data synchronization. Once synced, user credentials, solve history logs, pattern studio algorithms, and OpenCV scan outputs are persisted locally in SQLite via Drift and displayed in a read-only offline view.

## 🔐 Session & Authentication Architecture

### 1. Dual-Path Authentication Pipeline
1. **Flask Session Cookie Path (Web-Compatible):**
   - The user submits their web credentials (`username` and `password`) to `/api/v1/auth/login`.
   - FastAPI verifies the password against `UserModel` in the shared MySQL database using `werkzeug.security.check_password_hash`.
   - Upon verification, FastAPI derives an exact, cryptographically signed Flask session cookie (`SecureCookieSessionInterface` with `itsdangerous` using `Config.SECRET_KEY` and salt `'cookie-session'`).
   - The mobile client automatically persists this cookie (`session=<serialized_cookie>`) via `ApiClient` and attaches it to both the standard `Cookie` header and `X-Session-Cookie` header on all subsequent requests.
   - Any cookie generated by Flask can be verified by FastAPI, and any cookie generated by FastAPI is transparently honored by Flask.

2. **Firebase Auth Token Path (MySQL Identity Mapping):**
   - The user signs in via Firebase Auth and transmits their Firebase ID token (JWT) to `/api/v1/auth/firebase-login` or in the `Authorization: Bearer <token>` header.
   - FastAPI verifies the token claims (`email`, `uid`, `name`) via Firebase Admin SDK.
   - Rather than creating a competing or isolated user repository, FastAPI queries the existing MySQL `users` table:
     - If a user with a matching email already exists, it maps the Firebase session to that MySQL record.
     - If no match is found, a new user row is provisioned in MySQL with role `'user'` and starting bonus coins.
   - FastAPI then issues a native Flask session cookie for this mapped user, ensuring unified session management across all endpoints.

## ⚙️ Environment Configuration & Base URLs

The mobile app connects to the FastAPI backend service (`http://...:8000`).

| Platform | Default Base URL | Notes |
| :--- | :--- | :--- |
| **Android Emulator** | `http://10.0.2.2:8000` | Android loopback interface to host machine |
| **Windows Desktop** | `http://127.0.0.1:8000` | Native Windows execution |
| **iOS Simulator** | `http://127.0.0.1:8000` | macOS host loopback |
| **Physical Device (LAN)** | `http://<HOST_IP>:8000` | Configure via the in-app Settings gear icon |

### Firebase Configuration
- **Android:** Place `google-services.json` in `MobileApplication/android/app/google-services.json`.
- **iOS:** Place `GoogleService-Info.plist` in `MobileApplication/ios/Runner/GoogleService-Info.plist`.
- **Backend:** Optionally specify `FIREBASE_CREDENTIALS_PATH=/path/to/service-account.json` in your `.env` file for live production token verification. Development test tokens (`test_token_firebase:<email>`) are supported out-of-the-box for local testing.

## 🚀 How to Run

### Step 1: Start the FastAPI Backend Gateway
In the project root (`rubique/`):
```bash
python -m uvicorn fastapi_app.main:app --host 0.0.0.0 --port 8000 --reload
```
*(Verify health at: `http://127.0.0.1:8000/health`)*

### Step 2: Run the Mobile Application
Navigate into `MobileApplication/`:
```bash
cd MobileApplication
```

#### Run on Windows Desktop:
```bash
flutter run -d windows
```

#### Run on Android:
```bash
flutter run -d <android-device-or-emulator-id>
```

#### Run on iOS:
```bash
flutter run -d <ios-simulator-id>
```

#### Run on Chrome (Web Preview):
```bash
flutter run -d chrome
```

## 💡 Structural Assumptions & Integration Decisions

1. **Session Cookie Protocol:**
   Flask default sessions use `URLSafeTimedSerializer` with salt `'cookie-session'` and HMAC-SHA1 signature. FastAPI's `fastapi_app/session_manager.py` uses Flask's native signing serializer loaded with `Config.SECRET_KEY` so session cookies are 100% interoperable between both servers.
2. **Account Federation:**
   Firebase Auth tokens are mapped to existing MySQL user accounts by email. If the email is not in MySQL, an account is created in MySQL with a generated secure password hash and starting wallet balance. This maintains MySQL as the sole source of truth.
3. **OpenCV Vision Pipeline Split:**
   Computer vision image processing (CLAHE illumination normalization on LAB color space, contour-adaptive warping, and HSV median filtering) runs on the FastAPI backend in `fastapi_app/routers/cube_routes.py` (matching `controllers/api_controller.py`). The mobile client captures/picks the image and displays the real-time annotated output and color badges returned by the server.
4. **Offline Read-Only View:**
   Per the constraints, writes and solve processing require an active server connection. When offline, the app displays a prominent status banner and renders cached records (solves history, user credentials, pattern studio, and past scan results) directly from the local Drift SQLite database.
